# 전용면적 · 개략 배치도(평면도) — API 키와 데이터 얻는 법 (2026-11-08)

3D 트윈의 「전용면적」과 「개략 배치도」에 실제 값을 채우려면 무엇을 어디서 받는지 정리한다.
결론부터: **집합건물의 전용면적은 공개 API 로 받는다(이미 받는 중). 일반건축물의 전용면적과 모든 건물의 실제 평면도는
공개 API 가 없다** — 소유자 동의·임대인 제공·표본 통계로만 얻는다.

## 1. 지금 쓰는 키 두 개 (이미 있음)

| 키(환경변수) | 어디서 | 받는 것 | 쓰는 곳 |
|---|---|---|---|
| `DATA_GO_KR_SERVICE_KEY` | [공공데이터포털](https://www.data.go.kr) 회원가입 → [건축HUB 건축물대장정보 서비스(15134735)](https://www.data.go.kr/data/15134735/openapi.do) **활용신청**(자동승인) → 마이페이지의 **일반 인증키(Decoding)** | 표제부 · 층별개요(층 바닥면적·용도) · **전유공용면적(호실별 전용·공용)** · 전유부 | 수집 스크립트(`data/collectors/building_vacancy.py` 등) · 백엔드 Program(`program_sources.py`) |
| `VWORLD_API_KEY` | [브이월드](https://www.vworld.kr) 회원가입 → 인증키 발급 | 건물 외곽선 · 층수 · 높이 | `data/collectors/vworld_bldg.py` |

- 넣는 곳: 로컬 `.env`(`apps/backend/.env.example` 참고). 3D 트윈은 수집된 Gold 파일을 읽으므로 **배포(Cloud Run)에 키를 더 넣을 필요는 없다.**
- 건축HUB 는 개발계정 일일 호출 한도가 있다(포털 표기 10,000) — 수집 전 `python scripts/quota_preflight.py`, 런북은 `/quota` 스킬.
- 인증키는 **Decoding** 값을 쓴다(Encoding 값을 다시 인코딩하면 인증 오류).

## 2. 전용면적

### 2-1. 집합건물(구분소유 상가·오피스텔 등) — 공개 API 로 된다

- 오퍼레이션 `getBrExposPubuseAreaInfo`(전유공용면적). 호(`hoNm`)마다 `exposPubuseGbCdNm`(전유/공용) · `area` 행이 나온다.
- 지금 파이프라인(`data/pipelines/build_expos_units.py`)은 **전유 행만** 남긴다 → 화면의 「전용면적」 = 그 층 전유 호실의 합.
- **바로 할 수 있는 다음 단계:** 같은 응답의 **공용 행**도 남기면 호실별 공용면적과 계약면적(전용+공용) · 전용률을 **실측으로** 보일 수 있다.
  bronze 원본(`data/bronze/{거점}/*/bldg_ledger_raw.json` — git 밖, 수집 PC 에만 있음)에 공용 행이 남아 있으면 추가 호출 없이 계산된다.
  남아 있지 않으면 해당 거점만 다시 수집한다(쿼터 소모).

### 2-2. 일반건축물(건물 한 채 한 소유 — 공실 층 대부분) — 공개 API 에 없다

대장에는 층별 **바닥면적**(층별개요)만 있고, 계단·화장실 같은 공용을 뺀 전용면적 항목이 없다. 얻는 길은 셋이다.

| 경로 | 얻는 것 | 범위 | 방법 |
|---|---|---|---|
| 임대인 · 관리사무소 · 중개사 제공 | 층·호 전용면적, 계약 면적, 도면 | 협력한 건물만(가장 정확) | 요청 문안: `data/data-request-guide-2026-10-10.md` §6. 받은 값은 출처 「임대인 제공」으로 따로 표시 |
| 한국부동산원 R-ONE 상업용부동산 임대동향조사 마이크로데이터 | 표본 건물의 전용면적 · 공실면적 등(조사항목) | **표본**이라 전 건물이 아니다 | R-ONE 로그인 → 마이크로데이터 → 상업용 신청. 절차·문의 문안은 같은 문서 §2~§4. 공개 필드는 신청 후 확인 |
| 사용자(창업자) 입력 · 현장 실측 | 그 자리의 전용면적 | 입력한 자리 | 화면 입력 칸을 두고 「사용자 입력」으로 표시 |

- R-ONE 표본으로 **건물 유형·규모별 평균 전용률**을 구하면, 일반건축물 층에 「바닥면적 × 전용률 = 전용면적(추정)」을 보일 수 있다.
  이것은 추정값이라 「추정」 표시와 근거 표본을 같이 적어야 하고, 비율을 정하는 것은 사용자 결정이다(지금은 넣지 않았다).

## 3. 개략 배치도 · 평면도

### 3-1. 공개 API 로 되는 것 (이미 쓰는 중)

- 외곽선(브이월드) + 층 바닥면적·용도(층별개요) + 호실별 전용면적(전유공용면적).
- 화면의 개략 배치도는 이 셋으로 그린 **칸 크기만 맞는 그림**이다. 호실의 실제 위치 · 벽 · 계단 · 창 위치는 공개 자료에 없다.

### 3-2. 실제 평면도 — API 가 없고 발급 자격이 제한된다

- 평면도는 「건축물현황도」(배치도 · 평면도 · 단위세대 평면도)로, 정부24 가 아니라 **[세움터](https://www.eais.go.kr)** 에서 열람·발급한다.
- **평면도와 단위세대 평면도는 누구나 받을 수 없다** — 「건축물대장의 기재 및 관리 등에 관한 규칙」 제11조 제3항: 소유자 · 소유자 동의를 받은 자 ·
  소유자에게 설계·시공·**중개를 의뢰받은 자**(의뢰 사실 증명) · 국가·지자체 · 경매·공매 관련 등으로 제한된다.
  공용부분 평면도는 다른 구분소유자 동의도 필요하다는 법제처 해석(16-0045)이 있다. 최신 조문과 서식은 국가법령정보센터 원문과 시·군·구청 민원실에서 확인한다.
- 일괄 내려받는 API 는 없다. [건축데이터 민간개방 시스템](https://open.eais.go.kr)은 대장 속성·대용량 파일을 주지만 도면은 주지 않는다(2026-11-08 검색 기준).

그래서 실제 평면도를 쓰는 길은:

1. **임대인 · 중개사 협력** — 중개 의뢰를 받은 중개사는 위 요건으로 평면도를 받을 수 있다. 협력 건물의 평면도를 받아 「제공 도면」으로 서빙.
2. **사용자가 올린 도면** — 지금 화면의 「도면 올리기」(브라우저 안에서만 읽고 서버로 보내지 않음). 저장·공유하려면 개인정보·저작권 동의 흐름이 먼저다.
3. 받은 평면도에서 호실 위치를 그리면 3D 개략 배치를 실측 배치로 바꿀 수 있다(입력 형식 · 좌표 맞추기는 별도 설계).

## 4. 요약 — 무엇부터

1. (코드 · 무료) 전유공용면적의 **공용 행**을 살려 집합건물 호실별 공용·계약면적 · 전용률을 실측으로 표시.
2. (신청) R-ONE 마이크로데이터 신청 → 일반건축물 전용률 추정 근거 확보 → 추정 표시 여부는 사용자 결정.
3. (협력) 파일럿 건물의 임대인 · 중개사에게 전용면적 · 평면도 제공 요청(문안 있음).
