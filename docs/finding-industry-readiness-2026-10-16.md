# 상권 추천 미지원 6개 업종 조사 (2026-10-16)

## 직접 원인

`Find.tsx`는 `hasRanking()`이 거짓이면 「상권은 직접 골라요」를 표시한다.
판정은 `model_label` 존재 여부와 API의 `fit_unavailable_reason`을 사용한다.
현재 서빙 JSON에 실제 등장하는 라벨은 병원·숙박·약국·음식점·카페·편의점이다.

| 업종 | 현재 막힌 지점 | 추천을 위해 필요한 작업 |
|---|---|---|
| 술집 | `model_label=None`. 기존 대분류에서는 주점이 음식점에 포함된다 | 요리 주점·생맥주·유흥 주점 분리 학습 및 평가, 검증된 점수의 서빙 연결 |
| 미용·네일 | `model_label=None`. 기존 7종 사상 밖이라 학습 모집단에서 제외된다 | 미용실·네일·피부관리별 검증 및 서빙 연결 |
| 옷·잡화 | 동일. 소매 원천 행은 있지만 기존 모델 대상이 아니다 | 의류·신발·가방·잡화별 검증 및 서빙 연결 |
| 학원·교육 | 동일. 교육 원천 행은 있지만 기존 모델 대상이 아니다 | 교과·외국어·예체능·직업교육·스터디별 검증 및 서빙 연결 |
| 운동·여가 | 동일. 스포츠·여가 원천 행은 있지만 기존 모델 대상이 아니다 | 헬스·필라테스·골프·구기·PC방·노래방별 검증 및 서빙 연결 |
| 전시·공연 | `model_label=문화시설`이나 서빙 어휘에 없음. 세부 분류도 원천 대응 목록이 비어 있음 | 공연장·전시장·갤러리의 식별자·위치·시설 유형 원천 확보, Bronze→Silver→Gold 정규화와 중복 제거, 라벨 구축 후 학습·검증 |

앞의 다섯 업종은 **데이터가 전혀 없는 문제가 아니다.**
`data/config/industry_details.py`의 소분류 완전 일치 사상과 세부 업종 실험 경로가 이미 있다.
전시·공연의 결손은 시설이 실제로 0개라는 뜻이 아니라 현재 학습 원천·분류 계약으로
라벨을 만들지 못한다는 뜻이다. 소매의 「예술품」을 갤러리로 간주해서 채우지 않는다.

## 재현 가능한 근거

- `reports/industry_readiness_2026-10-16.json`: 현재 입력 해시, 미지원 사유, 세부 업종별 그래프 표본 및 실험 성능.
- `ml/reports/industry_detail_experiment_2026-10-16.json`: 현재 Gold로 다시 실행한 세부 업종 실험.
- `scripts/industry_readiness.py`: 코드의 업종 계약, Gold, 실험 보고서를 대조하는 진단 도구.

10월 9일 실험 보고서의 노드·엣지 해시가 현재 Gold와 달랐다. 과거 결과를 현재 성능으로
인용하지 않고 동일 실행에서 모델과 거점 사전분포 기준선을 다시 측정한다.
그래프 원시 노드 수에는 거점 간 중복이 있어 점포 전수로 표현하지 않는다.
학습기는 겹치는 점포를 가장 가까운 거점 중심에 귀속해 중복 제거한다.

```powershell
$env:OMP_NUM_THREADS='1'
$env:PYTHONIOENCODING='utf-8'
python -m ml.training.industry_detail_experiment --output ml/reports/industry_detail_experiment_2026-10-16.json
python -m scripts.industry_readiness --experiment ml/reports/industry_detail_experiment_2026-10-16.json --output reports/industry_readiness_2026-10-16.json
```

실험 명령은 기존 보고서가 있으면 덮어쓰지 않고 실패한다. 재실행할 때는 새 보고서명을 준다.
실험은 `save=False, resume=False, ckpt_every=0`으로 실행하며 기존 서빙 모델을 교체하지 않는다.

## 이번 코드 수정과 검증

- 미지원 상세 화면에 API의 실제 사유를 표시한다. 모든 결손을 「모델이 배운 업종이 아님」으로 표현하지 않는다.
- 업종 목록 통신 오류에는 재시도 화면을 표시한다.
- 지원하지 않는 업종의 추천 API 미리 받기를 생략한다.
- 진단 도구는 원천 대응이 없는 표본과 실험값을 `null`로 유지한다.

통과 조건: `data/tests/test_industry_readiness.py`, `data/tests/test_industry_detail.py`,

## 추천 활성화 전에 남은 일

1. 업종별 평가에서 부족한 항목을 구분하고, 실제 이용 가능한 입지 피처를 보강한다.
   야간 수요·고객 연령·시설 조건 등은 검토 후보이며 이번 실험으로 효과가 입증된 것은 아니다.
2. 같은 분할의 기준선과 비교하고, 상권 간 순위 검증 및 미관측 상권·시점 검증을 수행한다.
   현존 점포 업종 분류 성능은 매출·생존율 또는 상권 추천의 정답률이 아니다.
3. 검증된 업종만 서빙 계약에 연결한다. 세부 업종을 큰 업종으로 합칠 경우 점수 합산·가중의
   정의와 의미를 검증해야 한다. 임의 평균이나 다른 업종 점수로 연결하지 않는다.
4. 신규 산출물의 배포 포함 여부, API 지원 판정, 화면 순위·출처 표기를 함께 검증한다.

`ml/AGENTS.md`는 「실험은 --no-save로 돌리고 결과를 보고」하고 서빙 교체를 별도 판단으로
구분한다. 이번 작업은 실험·진단·오류 안내 개선이며 추천 활성화나 프로덕션 배포 완료가 아니다.
