## 1. PPPP 보고서 제거

「PPPP 보고서」 = 지도 탐색 레일의 **「상권 분석 보고서」** 단추 + 그 창(`AnalysisReportDialog`) + 오프라인 마케팅 기록에 붙은 종합 리포트(`PpppReport`) + PDF 만들기(`analysisPdf`) + 요약(`ppppReportSummary`).
**PPPP 보존 규칙(10-21)의 대상이 아니다** — 그 규칙은 Platform·Page·Posting·Program **네 구현 화면·레일의 네 트랙·진입로·랜딩 네 질문**을 지킨다. 보고서는 그 안에 붙은 도구였고, 레일의 네 트랙은 그대로다.
가드(`ppppScreens.test.tsx`)는 **손대지 않았고** 통과한다. `App.test.tsx` 의 레일 단추 목록에서만 「상권 분석 보고서」를 뺐다(그 테스트가 보고서를 세던 것이다).

- **지운 것**: `PpppReport.tsx/.css` · `AnalysisReportDialog.tsx` · `analysisPdf.ts` · `ppppReportSummary.ts` · 그 테스트 둘.
- **남긴 것(이름만 바꿈)**: 각 트랙의 결과를 한 작업 안에서 모아 두는 **보관소**. 보고서만 읽던 게 아니다 — Program 가설 설정이 앞선 단계의 결과(`workspace.platform/page/program`)를 이어받고 탭을 오가도 초안을 되살리는 데 쓴다.
  보고서를 지우며 이것까지 지우면 Program 이 깨진다. `ppppReportContext` → `workspaceRecords` · `PpppReportProvider` → `WorkspaceRecordsProvider` · `useReportCapture` → `useRecordCapture` 등 **보고서라는 이름을 걷었다**
  (`reportHandoff` → `postingResult` — Posting 이 Program 에 넘기는 최신 계산).
- **화면의 약속을 고쳤다**: 「검증 리포트에 포함됩니다」 · 「결과 리포트에 실립니다」 · 「리포트에 인테리어 조건 저장」 다섯 곳 — 지운 보고서를 약속하던 문장이다.
- `jspdf`(와 그것만 쓰던 html2canvas·dompurify·core-js 등)는 `package.json`·lockfile 에서 뺐다 — 공유 `node_modules` 는 그대로 두려고 `--package-lock-only` 로.

## 2. 층 배치도 사진 — 개략(가상) 배치도가 실제 배치도로

**흐름**: 건물주가 내 매물(층) 화면에서 사진을 고름 → 브라우저가 긴 변 1600px 로 줄여 JPEG 으로 다시 그림(EXIF 가 사라짐) → 서버가 형식·크기를 다시 보고 **EXIF·XMP·IPTC·주석을 한 번 더 뗌** → DB 에 저장 →
소유자 확인을 거쳐 **게시 중**인 매물이면 Page 건물 창의 그 층에서 개략 배치도 **대신** 사진이 보인다(되돌리기 단추 있음).

| 결정 | 내용 · 이유 |
|---|---|
| 저장 | DB 바이트(`direct_floor_plans` · 한 매물에 한 장). Cloud Run 은 디스크가 없고 버킷을 새로 들이지 않는다(가벼운 대안 먼저). 한 장 1.5MB · 한 사람 30MB |
| 공개 조건 | 매물과 같다(게시 중 + 소유자 확인 verified — L3). 숨김·일시중지·종료되면 사진도 안 보인다. 본인은 올린 직후에도 본다 |
| 메타데이터 | Pillow 가 없어 JPEG(APP1·APP13·COM)·PNG(eXIf·tEXt·zTXt·iTXt·tIME)를 직접 떼고, **화소는 건드리지 않는다**. 클라이언트를 믿지 않는다(테스트가 위치 문자열이 남지 않음을 확인) |
| 형식 | JPEG·PNG 만. mime 이 아니라 **바이트 머리**로 판정. 변 100~8000px |
| 응답 헤더 | `nosniff` · `Content-Security-Policy: default-src 'none'; sandbox` · 공개는 `public, max-age=300`, 본인은 `private, max-age=60` · 주소의 `v`(밀리초)가 바뀌면 새로 받음 |
| 화면의 말 | 「건물주가 직접 올린 사진 · PlaceOS 는 사진이 실제와 같은지 확인하지 않아요 — 현장에서 도면과 대조해 주세요」 — 소유자 확인은 **매물** 단위이지 **사진** 단위가 아니다 |
| 표가 없는 DB | 배포(자동)와 마이그레이션(수동) 사이 — 매물 기능은 그대로 서고 배치도 칸만 「준비 중」(503). 목록·상세의 `floor_plan` 은 null |
| 지우기 | 사진 지우기 · 매물 삭제 · 탈퇴(`remove_listing_rows` 가 부른다) 모두에서 지운다 |

⚠ **Neon 마이그레이션이 세 단계가 됐다**: `a7b8c9d0e1f2` → `b8c9d0e1f2a3` → **`c9d0e1f2a3b4`**(이번 것 · 표 1개). 사용자가 그 턴에 명시할 때만 올린다.
⚠ 개인정보: `privacy.html`(「층 배치도 사진」 행 · 탈퇴 파기 · 개정 이력) · `PrivacyNote` · `TABLE_TO_POLICY_WORD` 를 같이 고쳤다. 도면 속 개인정보(연락처 등)는 건물주가 가려 올리도록 화면에서 안내한다 — 서버가 사진 속 글씨를 읽지는 않는다.

## 3. 건물 이음 — 올린 층이 지도의 그 건물과 만나게

**발견한 구멍**: 건물주 등록 화면에는 건물 id(`building_id`)를 정하는 칸이 **없었다** — 주소로만 올려서, 직거래 매물이 Page 건물 창·흐름의 자리 상세(`BuildingDirectCard`)와 **만나지 못했다**.
사진이 Page 에서 보이려면 이 이음이 먼저였다. 그래서 등록 화면에 **「지도의 건물 찾기」**(`BuildingPicker`)를 더했다 — 상권의 건물 목록에서 건물주가 직접 고르면 건물 id · 좌표 · 대장 주소 · 층 목록이 채워진다(고칠 수 있다).
PlaceOS 가 주소로 건물을 **맞춰 주지 않는다**(지어내지 않는다). 목록에 없으면 비워 두고 주소로 올릴 수 있고, 그땐 지도 건물에 붙지 않는다고 화면이 알린다.
⚠ `building_id` 는 게시 중 바뀌면 소유자 확인을 다시 받는 칸(CORE_FIELDS)이다. 건물을 잘못 골라 남의 건물에 붙이는 것은 소유자 확인(등기 고유번호 대조)과 신고로 막는다 — 건물 이음 자체를 검증하지는 않는다.

## 4. Program 건물주 보기 — 있는 것만 잇는다

오프라인 마케팅 솔루션 탭 맨 위에 **누가 쓰나요: 창업자 / 건물주**를 더했다. 기본은 창업자 — 기존 화면(실행 카드 · 행사 연계 · 캠페인 기록)이 그대로다.
건물주 보기는 ① 지역 행사 연계 계획(`EventLinkPlanner`) ② 팝업·단기 사용으로 먼저 채우기(매물 등록의 거래 형태 → 등록 화면으로) ③ 입점 희망서로 수요 확인(→ 건물주용 희망서 목록)이다.
**탭은 빼거나 순서를 바꾸지 않았다**(보존 규칙 · `pppp_status` 가 탭 이름을 글자로 찾는다). 이 칸에서 돈이 오가지 않고 PlaceOS 는 행사를 열거나 섭외·대행하지 않는다(테스트가 「수수료·보수」 글자가 없음을 본다).

## 5. 랜딩 · 도움말 · 단계 머리 문구

`#how` 네 질문은 접지 않고 그대로 펼쳐 둔다(순서 · 접근성 불변). 질문 문구를 사용자 정의에 맞췄다:
Platform 「이 상권은 어떤 곳이지?」(유지) · Page 「어느 건물 몇 층이 비었지?」(유지) · Posting 「이 자리, 어떤 조건으로 건물주에게 전하지?」(11-15 의 「이 층 조건이면 얼마에 몇 개를 팔아야 하나」 대체) ·
Program 「오프라인에서는 어떻게 알리고 이어지지?」(11-15 의 「계약 전에 작게 어떻게 확인하나」 대체). H1 은 그대로(랜딩 테스트가 본다). 히어로 첫 줄 「창업자 전용 부동산 앱」 → 「창업자와 건물주를 잇는 부동산 앱」.
지도 탐색 단계 머리(`ExploreStep`)의 제목·설명·연결 문구도 정렬했고, Page 에는 「건물주이신가요? …올리기」, Posting 에는 「입점 희망서 쓰기」 줄을 **더했다**.
랜딩 테스트의 규칙(숫자는 거점 수뿐 · %·정확도 없음 · 금지 표현 없음)은 그대로 통과한다. 「Program 은 영업 중인 가게의 홍보는 다루지 않는다」 문장은 남겼다(FAQ 를 건물주·창업자 기준으로 고침).
