### A. 서울시 문화공간 정보 `culturalSpaceInfo` — 이번 조사의 핵심

**요청**: `GET http://openapi.seoul.go.kr:8088/{KEY}/json/culturalSpaceInfo/1/3/` 후 `1/1000`, `1001/1100` (총 2콜 전량).

**응답 요약**
- `list_total_count` = **1,096**, `RESULT.CODE` = `INFO-000`.
- 필드: `NUM, SUBJCODE, FAC_NAME, ADDR, GNGU, X_COORD, Y_COORD, PHNE, FAX, HOMEPAGE, OPENHOUR, ENTR_FEE, CLOSEDAY, OPEN_DAY, SEAT_CNT, ETC_DESC, ENTRFREE, SUBWAY, BUSSTOP, YELLOW, GREEN, BLUE, RED, AIRPORT` (+ 이미지·설명 HTML).
- 첫 행 인용: `SUBJCODE="기타" FAC_NAME="DDP(동대문디자인플라자)" ADDR="서울특별시 중구 을지로 281" GNGU="중구" X_COORD="37.567…" Y_COORD="127.009…"`.
- ⚠ **`X_COORD` 가 위도, `Y_COORD` 가 경도다**(이름과 반대). 좌표가 서울 범위(위도 37~38, 경도 126~128)인 행 1,095/1,096. 나머지 1행은 `X_COORD="37.5718961547884~2"` 같은 오염값(한국미술관) — 파서가 걸러야 한다.

**유형 분포 (`SUBJCODE`)**

| 코드 | 행 | 비고 |
|---|---:|---|
| 미술관/갤러리 | 271 | 한 덩어리 |
| 기타 | 235 | DDP·예술공장·노들섬 등 |
| 공연장 | 194 | 세종문화회관·LG아트센터·블루스퀘어·롤링홀 등 |
| 도서관 | 177 | 이번 업종 대상 아님 |
| 박물관/기념관 | 171 | |
| 문화원 | 28 | |
| 문화예술회관 | 20 | |

`전시장`·`갤러리`·`미술관`·`박물관` 단독 코드는 **0행**이다.

**갤러리/미술관 분리 가능성 (이름 규칙 실측, 271행)**: 이름에 `갤러리·화랑·gallery` 포함 120 · `미술관·뮤지엄` 포함 56 · 둘 다 2 · **어느 쪽도 아닌 행 97**(예: 학고재, 아트선재센터, 인사아트센터, 코엑스전시장, 한국공예문화진흥원). 이름 규칙만으로는 약 36%가 분류 불능이다.

**기타 실측 사실**
- `ADDR` 채움 1,096/1,096 · `SEAT_CNT` 채움 **18/1,096**(공연장 194행 중 5행) → 좌석수 피처로는 못 쓴다.
- 고유 시설명 1,092 · 고유 주소 1,042. 같은 주소에 2개 이상 시설이 있는 주소 44곳 중 **유형이 서로 다른 곳 28곳**(예: 세종로 175 `세종문화회관`=공연장, `세종문화회관 미술관`=미술관/갤러리; 을지로 281 DDP=기타, 동대문역사관=박물관/기념관). 건물 단위 귀속에서 한 건물에 복수 유형이 선다.
- 구별 분포 상위: 종로 254 · 강남 105 · 중구 80 · 용산 66 · 서초 56 (도심 편중).
- **갱신일·기준일 필드가 없다.** 수집일만 기록 가능하다. 시설의 폐관·이전 반영 여부를 응답으로 알 수 없다.
- 라이선스: 응답에 명시 없음 → **미확인**(데이터셋 상세 페이지의 이용허락 조건을 사람이 확인해야 한다).
- 상업 갤러리 포함 여부: 포함된다(예: 필 갤러리·갤러리비케이 이태원·알부스갤러리·모다 갤러리). 다만 **전수 분모가 없어** 얼마나 빠졌는지는 잴 수 없다. 상가정보 `예술품 소매업`(81거점 반경) 중 상호에 갤러리·화랑·아트센터·미술관이 든 점포 401개와 대조하면, 이름 완전일치로 연결되는 것은 25개, 좌표 50m 안에 문화공간 시설이 있는 것이 136개뿐이다. **문화공간 정보는 상업 갤러리의 일부 표본**이다.

**거점 커버리지(81 서빙 거점, `stores_radius_m`=700m 안)**

| 유형 | 거점 반경 안 / 서울 전체 |
|---|---|
| 공연장 | 117 / 194 |
| 미술관/갤러리 | 174 / 271 |
| 문화예술회관 | 8 / 20 |
| 박물관/기념관 | 85 / 171 |
| 기타 | 105 / 235 |
| 전체 | 540 / 1,096 (한 시설이 복수 거점 반경에 드는 경우 88건, 최근접 귀속 시 시설을 가진 거점 **77/81**) |

시설이 몰린 거점은 혜화(61)·익선(48)·삼청(47)·시청(25)·서촌(25)·홍대(19) 순이다.

**판정**
- 공연장 — **쓸 수 있음.** 식별(이름+주소)·좌표·유형이 모두 나온다. 단 시설 고유 ID 가 없어 우리가 키를 만들어야 한다.
- 갤러리·미술관 — **조건부.** 분리 규칙이 필요하고 사람 승인이 선행한다(§5).
- 전시장 — **조건부.** 별도 코드가 없고 `기타`·`미술관/갤러리`에 흩어진다(예: `코엑스전시장`이 미술관/갤러리에 있음).

### B. 문체부 전국 문화기반시설 총람 (Bronze 기수집)

**방법**: `facilities_2025.xlsx`(1,669,999바이트, 기준 2025-01-01, 표준 라이브러리로 시트를 열어 집계).

- 시트 10개: 국립도서관·공공도서관·**박물관·미술관**·생활문화센터·**문예회관**·지방문화원·문화의집·문학관·지역문화재단.
- 서울 행: 박물관 약 137(시트 합계행 137, 이름 매칭 대상 138) · 미술관 43(시트 합계 43; 이름 매칭 대상 46) · 문예회관 29 · 생활문화센터 19.
- 필드: 시설명·주소·연락처·개관일, 박물관·미술관은 `국립/공립/사립/대학` · `1종/2종/미등록`(등록 여부). 문예회관은 대공연장 객석수 열이 있으나 서울 29행 중 3행만 채워져 있다.
- ⚠ **좌표가 없다.** 주소를 좌표로 바꾸는 단계가 추가로 필요하다(지오코딩 원천·약관은 이번에 프로브하지 않았다 — **미확인**).
- ⚠ **상업 갤러리·민간 공연장 소극장은 사실상 범위 밖**이다(체크리스트 `placeos-data-acquisition-checklist.md` 28행도 같은 경고: "상업 전시장·갤러리 부족분은 해당 운영기관에 시설 목록 요청").

**원천 간 중복·불일치 (표본 확인)**
- 총람 서울 미술관 46개를 A 와 이름(부분일치 포함)으로 대조: **36개 연결**(35 → `미술관/갤러리`, 1 → `공연장`), 10개 미연결(예: DDP디자인뮤지엄, 롯데뮤지엄, 밀알미술관, 아모레퍼시픽미술관, 한가람디자인미술관). 미연결은 이름 표기 차이로 보이는 것과 A 에 아예 없는 것이 섞여 있어, 이름 일치만으로는 정체를 단정할 수 없다. 주소·좌표 매칭이 필요하다.
- 총람 서울 문예회관 29개 중 27개 연결: A 의 유형이 `문화예술회관` 16 · `기타` 7 · `공연장` 4 로 **같은 시설이 서로 다른 유형**이다. 즉 「공연장」 정의에 문예회관을 넣을지는 규칙 결정이다.
- 총람 서울 박물관 138개 중 112개 연결(`박물관/기념관` 109). 부분일치라 오매칭이 섞였을 수 있다(공연장·미술관/갤러리로 간 3건은 의심 대상).

**판정**: **조건부.** 단독 라벨 원천으로는 부적합(좌표 없음, 공공시설 위주, 기준일 9개월 경과)하나, A 의 유형 보강(미술관 **등록 여부 1종/2종**, 국공립/사립)과 누락 확인에는 쓸 수 있다.

### C. KOPIS 공연시설 — 키 필요

`KOPIS_API_KEY` 가 설정돼 있지 않다(이번 세션에서 환경변수 존재 여부만 확인, 값은 읽지 않음). 프로브하지 않았다.
이 원천이 줄 것으로 **기대되는** 것(공개 명세 기억일 뿐 실측 아님): 시설 목록·시설 상세(좌표·좌석수·특성). `industry_details.py` 가 요구하는 「KOPIS 시설·공연 연결」이 이 원천이다.
**미확인 사항**: ID 형식, 좌표 유무, 서울 건수, 이용 조건, 일일 호출 한도. 키가 생기면 시설 목록 1콜 + 시설 상세 1콜로 확인한다(§6).
판정: **판정 보류.** 공연장 모집단의 정본 후보지만, A 에 공연장 194행이 이미 있으므로 급하지 않다. A 와의 **교차검증용**으로 가치가 크다.

### D. 문화포털 공연전시정보 (한국문화정보원, data.go.kr)

**요청**: `GET https://apis.data.go.kr/B553457/cultureinfo/period2?serviceKey=…&from=20261001&to=20261031&PageNo=1&numOfrows=2&sido=서울`

**1차 응답(신청 전, 2026-10-16)**: HTTP 403, `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`, `returnReasonCode=30` ("등록되지 않은 서비스키"). 이 서비스에 활용신청이 안 돼 있었다.

**2차 응답(신청 후, 2026-10-17, 같은 요청 1콜)**: HTTP 200 `application/xml`, `resultCode 00 정상입니다.`, `totalCount 1466`.
- 사용자가 data.go.kr 에서 「한국문화정보원_한눈에보는문화정보조회서비스」 활용신청을 마쳤다(심의유형 자동승인). 기존 `DATA_GO_KR_SERVICE_KEY` 로 그대로 호출된다 — 새 키·`.env` 변경은 필요 없다. 현행 경로는 위 `cultureinfo/period2` 가 맞다(처음 시도한 `…/nopenapi/rest/publicperformancedisplays/period` 는 코드 12 로 폐기).
- 응답 필드(item): `serviceName, seq, title, startDate, endDate, place, realmName, area, sigungu, thumbnail, gpsX, gpsY`. **시설 ID·주소·시설 유형 필드는 없다.** 시설은 `place`(이름)와 좌표로만 식별되고, `realmName` 은 이벤트 분야다.
- 단위가 **공연·전시 이벤트**다. 시설 목록이 아니다 — 이벤트의 `place`·좌표에서 시설 활동성(최근 전시·공연이 열린 장소)을 보는 보조 원천이다. 시설 유형을 이 원천에서 얻을 수 없으므로, 전시·공연 업종 통합(§5)의 포함 여부 판정은 A·B 의 유형 어휘가 맡는다.
- ⚠ 표본 2행에서 본 의심(**전수 확인 아님**): 요청에 `sido=서울` 을 줬는데 첫 행이 `area=대구` 였다 → 지역 필터 파라미터명이 다르거나 필터가 안 먹을 수 있다. 둘째 행은 `serviceName=공연` 인데 `realmName=전시` 로 두 라벨이 어긋났다. 수집기를 만들기 전에 파라미터 명세(공공데이터포털 상세 페이지)로 확인한다.
- 판정: **보조 원천으로 사용 가능.** 시설 마스터는 서울 문화공간 정보(A)가 맡는다. 이벤트를 A 시설에 붙이려면 `place` 이름·좌표 매칭이 필요하고 오매칭 위험이 있다(미검증).

### E. 소상공인 상가정보 — 불가 (실측)

기수집 Bronze 81거점 전수(중복 제거 257,376점포)로 센 결과:
- 대분류 `예술·스포츠` 아래 중분류는 `유원지·오락`·`스포츠 서비스`·`도서관·사적지`뿐이다. **공연장·전시장·미술관·박물관 소분류가 없다.**
- KSIC `R90110`(공연시설 운영업) 점포는 **1건**(상호 「국제아트딜러협회」, 소분류는 「그 외 기타 교육기관」)이다. 박물관(R90221) 점포는 0건. 즉 공공 문화시설은 상가업소 DB 에 들지 않는다.
- 갤러리라는 이름은 대부분 `예술품 소매업`에 있다(상호에 「갤러리」가 든 점포 334개 + Gallery 6개). 그 밖에 미용실 35·카페 28·여성 의류 26·구내식당 22 등에도 「갤러리」가 상호로 쓰인다. **상호 문자열로 갤러리를 추정하면 오라벨이 대량으로 생긴다.**
- 따라서 「소매의 예술품을 갤러리로 간주하지 않는다」는 금지는 실측으로도 맞다. 판매 업소와 전시 시설은 다른 모집단이다.

### F. 서울 인허가 `LOCALDATA_*` — 공연장·전시 서비스 미확인

- 2026-08-23 문서는 `LOCALDATA_{CCGGSS}` 전수 스캔으로 **살아 있는 161종**을 찾았다고 적었으나, 그 161종 **목록 산출물은 저장소에 없다**. 수집 대상 27종(`seoul_licensing.SERVICES`)과 이번 15종에 공연장·전시장은 없다. 161종 중에 있는지는 **미확인**.

## 4. 제안 — 정규화 설계 (구현하지 않음)

### 4-1. 최소 스키마

```
Bronze  data/bronze/{city-wide|culture}/{수집일}/culturalSpaceInfo.json   # 원응답 그대로, append-only
Silver  data/silver/culture/facilities.json
Gold    data/gold/culture/hub_facilities.json     (거점 귀속 포함)
```

| 필드 | 설명 |
|---|---|
| `facility_key` | 우리가 만드는 키. 원천에 고유 ID 가 없다 → `norm(시설명) + norm(도로명주소)` 해시 |
| `name`, `address_raw`, `address_norm` | 원문 보존 + 정규화 주소 |
| `lat`, `lon` | A 는 `X_COORD`=위도, `Y_COORD`=경도 — **스왑 주의**. 범위 검증(37~38 / 126~128) 후 결측·오염행은 `null`로 두고 사유 기록 |
| `source` | `seoul_culture_space` / `mcst_directory_2025` / (후속) `kopis` |
| `source_type_raw` | 원천 유형 코드 원문(`SUBJCODE` 등) |
| `facility_type` | 파생 — `performance_hall` · `exhibition_hall` · `gallery` · `museum_art` · `other`. **승인된 규칙 문서에 따라서만** 생성하고 규칙 버전을 필드로 남김 |
| `type_confidence` | `source_code`(원천 코드 직접) / `name_rule` / `cross_source` / `unresolved` |
| `collected_at`, `source_ref_date` | 수집일(필수) / 원천 기준일(B 는 2025-01-01, A 는 `null` — 원천이 주지 않음) |
| `hub_slug`, `hub_distance_m` | 거점 귀속(§4-2) |
| `dup_group` | 중복 제거 그룹 ID |
| `seat_count` | A 의 `SEAT_CNT` — 결측이 대부분이라 **선택 필드**, 피처로 쓰지 않는다 |

데이터 매니페스트(`data/manifests/`)에 수집 메타 1건: 요청 URL(키 제외)·호출 수·`list_total_count`·응답 해시·수집일.

### 4-2. 거점 귀속·중복 제거

1. **거점 귀속**: 시설 좌표 → 81 서빙 거점(`page_hubs.ACTIVE_HUBS`)의 `stores_radius_m` 안 후보를 구하고 **가장 가까운 거점 중심에 1건만 귀속**한다. 학습기가 점포에 쓰는 규약("겹치는 점포를 가장 가까운 거점 중심에 귀속")과 같다. 이번 실측에서 복수 거점 겹침 88건이 있었다. 반경 밖 시설(555/1,096)은 버리지 않고 `hub_slug=null`로 남긴다.
2. **중복 제거 순서**(원천 내 → 원천 간):
   - 원천 내: `facility_key` 동일 + 좌표 30m 이내 → 동일 시설. A 의 이름 중복 4건(살롱쿤스트·MGFS100갤러리·ADM 갤러리·중랑구립정보도서관)이 첫 검증 표본이다.
   - 원천 간(A↔B): 정규화 주소 일치 우선, 이름 부분일치는 보조. 이름만으로 합치면 안 된다(§3 의 박물관 3건 오매칭 의심).
   - 같은 주소의 서로 다른 시설(세종문화회관 / 세종문화회관 미술관)은 **합치지 않는다**. 건물 단위가 아니라 시설 단위가 모집단이다.
3. **우선순위**: 좌표·유형은 A, 등록 여부·국공립 구분은 B 로 **보강**만 하고 서로 덮어쓰지 않는다. 불일치는 `conflict` 로 기록한다.
4. **개인정보**: 시설 연락처(`PHNE`)·홈페이지는 업소 정보이나 개인 휴대번호가 섞일 수 있다. Silver 이후에는 쓰지 않는다.

### 4-3. 학습 가능성에 대한 숫자 (정직하게)

- 거점 반경 안 시설: 공연장 117 + 미술관/갤러리 174 = **291**. 현재 세부 업종 실험의 전체 노드가 61,165(테스트 12,243, 약 20%)이므로 291은 **전체의 0.5% 미만**이다. 같은 분할이면 테스트에 약 58개가 떨어진다(산술 추정). 이 크기에서는 업종 하나의 Top-3 차이 신뢰구간이 매우 넓어 **KPI 규칙 2(불확실성 동반)상 `실력`으로 판정되기 어렵다.** 헬스장(300)·PC방(96)·골프(109)가 이미 기준선과 비슷한 수준에서 멈춘 것과 같은 영역이다.
- 이 원천의 시설은 **상가정보 점포가 아니다.** 현재 GNN 노드는 점포이므로, 시설을 노드로 넣으려면 그래프 정의(노드 종류·간선)를 바꾸는 별도 설계 판단이 필요하다. 라벨은 만들 수 있어도 **기존 학습기에 그대로 꽂히지 않는다.**
- 공공 시설(도서관·박물관 등) 편중이 있어 「입지가 어떤 시설을 부르는가」와 「공공이 어디에 짓는가」가 섞일 위험이 있다. 이것은 가설이며 이번에 검증하지 않았다.
- 따라서 단계는 **(1) 시설 마스터 구축 → (2) 거점별 집계(존재·밀도)를 Platform 에 지표로 서빙 → (3) 모델 라벨은 표본이 더 모인 뒤**가 현실적이다. (2)는 추천 모델 없이도 화면에 사실을 보여 줄 수 있어 「미지원」 안내 문구를 구체화한다.
