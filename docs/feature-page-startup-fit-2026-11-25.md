# Page — 빈 층 「창업 가능 등급 · 건물주 등록」 (2026-11-25)

사용자 요청: 「PlaceOS Page 에 공실들 중 실시간으로 창업 가능, 건물주 공실 등록 확인 가능하도록」.

## 무엇이 생겼나
- **API** `GET /api/v1/commercial-districts/{district}/startup-fit?building_id=&certainty=&detail=` — `services/startup_fit.py`
- **건물 상세 패널** 「창업 가능 · 건물주 등록 · 실시간」(`components/StartupFitPanel.tsx`) — 빈 층마다 등급 배지(기호 + 글자) · 건물주 등록 · 이유 펼치기 · 「다시 확인」
- **목록 거르기** 「창업 · 건물주」(MapShell) — 창업 여력 있음 · 가능 층이 있는 건물 / 건물주 등록 층이 있는 건물. 처음 고를 때만 `detail=false` 로 부른다

## 등급 규칙 (위에서부터)
| 등급 | 조건 |
|---|---|
| 창업 어려움(C) | 일반 창업 6업종 모두 용도변경 필요 · 용도지역 금지 · 공공·기반 시설 · 1층 기준 세 가격대 모두 적자 중 하나 |
| 조건부 · 확인 필요(B) | 행위제한 미수집 · 상층 임대료로만 흑자 · 300㎡ 이상 · 건물 상업층 전체 공실 · 판매시설 층 · **추정 빈 층** 중 하나 |
| 창업 여력 있음(A1) | 위 둘이 아니고, 1층 기준 순익률이 서울 같은 가격대 평균 영업이익률(KOSIS 2024 `profit_rate`) 이상인 가격대가 있음 |
| 창업 가능 · 여력 얇음(A2) | 위 둘이 아니고, 흑자인 가격대는 있지만 모두 서울 평균 미만 |

- 법·용도는 `use_check.check` 를 일반 창업 6업종(카페 · 음식점 · 편의점·생활 · 미용 · 학원 · 운동)으로 돌린다. Gold 층 대장에 용도코드가 없어
  대장 용도명으로 별표1 호를 근사한다(`HO_BY_NAME` · 이름으로 못 정하면 None → 「확인 필요」). 실시간 용도코드로 돌린 집계(finding-eum-landuse-2026-11-15 §4)와
  업종·판정별 비율 차이 최대 1.5%p.
- 수지는 Posting 3-Tier 를 그 층에 **1층 기준**으로 돌린다 — 매출에 층 보정이 없어 상층을 층 계수 임대료로만 보면 낙관으로 기운다. 기준선은 새로 정하지 않고
  KOSIS 서울 평균에서 가져온다(유닛 순익률 ≥ 평균 영업이익률 ⇔ 매출 대비 임대료 비중 ≤ 서울 평균 `rent_rate`).
- 3층 이상은 참고만(찾아오는 업종 위주) — 등급을 바꾸지 않는다.

## 건물주 등록
- 요청마다 게시 중 · 소유자 확인 매물(L3)을 **건물 ID + 층**으로 맞춘다(앱의 `ownerListingsOf` · `BuildingDirectCard` 와 같은 키). 등급 부분만 상권별 600초 기억한다.
- 직거래 표가 없으면 `owner_status=not_ready`, DB 를 못 읽으면 `unavailable` — 둘 다 **0 건이 아니다.** 화면은 「확인 준비 중 / 모름」과 `owner_note` 를 적고,
  목록 거르기는 이때 거르지 않는다(모르는 것을 없다고 세지 않는다).
- 소유자 이름 · 등기 정보(L5)는 싣지 않는다. 매물을 고르거나 순위를 매기지 않는다(직거래 규칙).

## 검증 (2026-11-25)
- 2026-11-23 보고서용 분류(SpaceOS---Page `integrations/placeos-vacancy-classification`)와 서울 확인 빈 층 11,630개 중 **11,628개 등급 일치**.
  남은 2개는 이 서비스가 앱의 `viable`(반올림 전 순익)을 그대로 쓰기 때문이다 — 이쪽이 맞다.
- 로컬 SQLite 에 실제 API 흐름(가입 → 매물 → 소유자 확인)으로 매물을 게시하면 그 건물 · 그 층에만 「건물주 등록 1건」이 붙는다(`tests/test_startup_fit.py` 가 고정).
- 프로덕션은 2026-11-23 기준 `/direct/listings` 503(직거래 표 없음) — 배포 뒤 이 패널은 「건물주 등록 확인 준비 중」으로 나온다. 마이그레이션 3단계를 적용하면 ready 가 된다.

## ⚠ 함정 — 상권 반경이 겹친다
같은 층이 반경이 겹치는 상권 Gold 에 모두 들어 있다(같은 `vfu-` id · 상권마다 다른 수지). 그래서 **상권별 합은 서울 층 수가 아니다** —
서울 확인 빈 층은 상권별 합 11,630 · 서로 다른 (건물, 층) 10,371 (2026-11-25 Gold). 서울 전체 수를 말할 때는 (건물 ID, 층)으로 중복을 걷어 낸다.
