### 인허가 → 건물 폴리곤(PNU) 조인율 — 폐업 행도 영업 행만큼 붙는다

기존 `build_page_master._licensed_pip` 는 **영업 중 행만** 귀속한다. 같은 보정(EPSG:2097 변환 + 지번주소 자가 보정 오프셋)을 폐업 행까지 적용해 쟀다
(`scripts/probe_licensing_parcel_join.py` · 결과 `reports/licensing_parcel_join_2026-11-17.json`). 분모는 **거점 폴리곤 bbox 안의 행**이다(인허가는 구 단위라 거점 밖 행이 대부분).

| 거점 | 영업: 건물에 붙은 행 / bbox 안 | 폐업: 건물에 붙은 행 / bbox 안 | 주소 PNU 와 일치(영업·폐업) |
|---|---|---|---|
| garosugil | 1,591 / 1,871 = **85.0%** | 4,087 / 4,699 = **87.0%** | 96.6% · 95.1% |
| hongdae | 2,405 / 2,803 = **85.8%** | 6,594 / 7,800 = **84.5%** | 99.8% · 99.8% |
| gangnam | 2,666 / 3,760 = **70.9%** | 6,810 / 9,455 = **72.0%** | 92.6% · 91.2% |

- **폐업 행이 영업 행과 같은 비율로 붙는다**(차이 ≤ 2%p) — 폐업 업소에 좌표가 덜 정확하다는 흔적이 없다. 폐업 행의 PIP 결과가 지번주소 PNU 와 일치하는 비율도 91~99.8% (n = 3,251~6,000).
- 복제본 검증: 영업 행의 보정 오프셋이 `_licensed_pip` 와 일치(가로수길 -256.6 vs -256.7m · 홍대 -255.5 vs -255.5m). 귀속 수는 `_licensed_pip` 가 (업소명, 지번주소) 중복(314·313건)을 먼저 빼므로 이 프로브보다 85·94건 작다 — 중복 제외분의 귀속 몫과 크기가 맞다.
- bbox 안인데 건물에 안 붙는 15~29% 는 도로·공터·원형 반경 모서리일 수 있으나 **어디서 빠지는지(대로변에 몰리는지)는 안 봤다** — 접도별 생존율에서 이 누락이 접도와 상관이면 편향이다. 다음 점검 항목.
- **3개 거점(전체 81 중)만 쟀다.** 수치는 표본이고 서울 평균이 아니다. 강남이 낮은 것은 폴리곤 범위 대비 bbox 가 넓기 때문일 수 있다(미확인).
- 필지 접도(§2) 조인 99.2% 와 합치면 **「폐업 업소 → 건물 → 접도」 경로가 3거점에서 열린다.**

(정정) 이 문서의 이전 판은 「환경에 pyproj·shapely 가 없다」고 적었다. **pyproj 3.7.2 는 이미 있었고 없던 것은 shapely 뿐**이었다 — 첫 import 실패가 shapely 였는데 둘 다 없다고 일반화했다. 11-17 에 shapely 2.2.0 을 설치했다(`data/requirements.txt` 에 추가).

## 4. 블로그 게시량

수집기: `python -m data.collectors.naver_digital_exposure --blog` → `data/bronze/platform13/2026-11-17/naver_blog_exposure.json` (거점 81 × 질의 2 = 162질의, 오류 0).
저장하는 것은 게시일 집계·`total`·거점 토큰 정밀도뿐이다 — 본문·스니펫은 남기지 않는다.

### 4-1. 월별 건수는 안 된다 → 일평균 게시율

162질의 **전부 1,000건에서 잘렸다**(API 상한). 그 1,000건이 덮는 기간은 사분위 5 / 9 / 23일, **137/162가 31일 이하**(가로수길 시험 수집: 8일).
월 단위로 자르면 대부분 이번 달 하나만 담긴다. 그래서 거점별 지표는 `rate_per_day` = 1,000건 ÷ 창 일수다. 상한(1일 창에 1,000건)에 걸린 질의는 2건 — 이 둘은 하한값이다.
인기 거점은 창이 며칠이라 월 1회 적재로는 그 달의 일부 주만 본다 → **주 1회**가 맞다(질의 1,620콜/회, 일일 한도 25,000 안).

### 4-2. 질의가 거점을 재고 있나 — 첫 수집은 아니었다

첫 수집(`「서울 {거점명} 맛집」`, 파일 `naver_blog_exposure_loose_query_invalid.json`)은 **무효**다.
`서울 숙대입구 맛집` = total 5,948,281, 최신 100건 중 「숙대입구」 포함 **2건**. 거점명이 아니라 「서울 맛집」 전반을 잰 것이다. 정확일치 `"숙대입구" 맛집` = total 186,666 · 92건.
그 수집의 거점 간 율 순위와 데이터랩 검색 관심도(기준어 보정, 최근 12개월) 의 Spearman = **0.315**, 율 상위 5곳(sukmyung·seongsu·namdaemun·konkuk·gwangjang)은 데이터랩 상위와 겹치지 않았다.

재수집(`"{거점 키워드}" 맛집|카페` 정확일치, 접두어 「서울」 제거, 거점 키워드는 데이터랩과 같은 것):

| 지표 | 값 |
|---|---|
| 정밀도(제목·스니펫에 거점 토큰이 든 비율) 사분위 | 0.38 / 0.62 / 0.87 |
| 정밀도 0.5 미만 질의 | 63 / 162 (0.2 미만 22) |
| 두 질의 모두 정밀도 ≥ 0.5 인 거점 | **45 / 81** |
| 거점 간 율 순위 ~ 데이터랩 순위 (Spearman) | 전 81거점 **0.365** · 정밀도 필터 45거점 **0.403** |

- 정밀도는 **하한**이다: 토큰이 공백을 포함하면(`성수동 카페거리`) 낱말이 전부 있어야 맞다고 세고, 본문은 API 가 주지 않는다. seongsu 0.025 는 이 때문일 수 있다(정확일치 시험에서 「성수동」 단독은 52~60건).
- 반대로 「서울」 접두어를 뺐으므로 **동명이지(타 시도 같은 이름)** 오염은 이 지표로 못 잡는다(11-17 이전 실측 7.3%, jangan 43.6%).

### 4-3. 판정

- 블로그 율은 **주(主) 노출 변수가 못 된다.** 데이터랩과의 순위 상관이 0.37~0.40 이라 둘이 같은 것을 재는지 입증되지 않았고, 정밀도 0.5 미만 질의가 39%다.
- **쓰임**: 데이터랩 검색 관심도가 주 변수, 블로그 율은 **정밀도 ≥ 0.5 인 45거점의 보조·강건성 검정**으로만 쓴다. 감성은 여전히 안 만든다.
- 쌓는 일은 계속한다 — 과거로 못 돌아가는 유일한 변수이고, 정밀도가 낮은 거점의 질의를 고칠 근거(거점 키워드 지정)가 이 스냅샷에서 나왔다.
- 아직 **적재는 1회분**(2026-11-17)뿐이고 주 1회 자동 실행은 등록하지 않았다(§6).
