# [사전등록 → 실측] LSTM Δ 타깃 — 지속성을 모델의 기본값으로 만든다 (2026-09-26)

## 0. 사전등록 (학습을 돌리기 **전에** 적었다)

### 왜

09-24 누수 차단 재학습 뒤 오차 축이 `열위`다 — 모델 MAE 2.224 vs 지속성(예측=직전
분기값) 1.190, 기술점수 −86.9% [−116.8%, −57.1%]. 분기 공실 프록시는 자기상관이 강해
지속성이 원래 센 대조군이다. 그런데 지금 모델은 **수준(level)** 을 직접 맞히므로,
신호가 없을 때 기본값이 "직전값"이 아니라 "train 평균 근처"다 — 지속성을 이기려면
직전값을 스스로 복원하는 것부터 배워야 한다.

### 무엇을 바꾸나 — 타깃 모수화 하나

- `target_mode="delta"`: 모델이 **Δ = 다음 분기값 − 직전 분기값** 을 맞히고, 예측은
  `직전값 + Δ̂` 로 복원한다. 모델 출력이 0 이면 예측이 정확히 지속성이다.
- 표준화 통계(Δ 의 y_mu·y_sd)는 종전과 같이 **train 행에서만** 낸다.
- 방향 판정은 그대로 `sign(pred − prev)` = `sign(Δ̂)` 다.

### 설계 — 규약은 건드리지 않는다

- 그리드: 기존 8 조합 × `target_mode ∈ {level, delta}` = **16 시행**. level 8 개는
  09-24 와 같은 시드·같은 코드라 같은 결과가 나와야 한다(재현성 점검 겸).
- **선택 기준은 바꾸지 않는다** — val 방향정확도, 동률이면 val MAE. 09-24 finding 이
  "기준을 MAE 로 바꾸면 metric shopping" 이라 적어 둔 그대로다. 그래서 Δ 가 val MAE 로
  이겨도 val 방향에서 지면 **채택되지 않는다.** 그 결과도 그대로 적는다.
- test 는 선택된 1 개에 대해서만 보고한다(`test_used_once`).

### 무엇이 성공인가 — 판정은 `kpi_baseline` 의 verdict

| 결과 | 뜻 |
|---|---|
| 오차 `실력` | 가설 지지 — 지속성 위에 모델이 얹는 것이 있다 |
| 오차 `구분불가` | 지속성 수준까지는 왔다 — 모델이 더하는 것은 이 표본으로 못 가른다 |
| 오차 `열위` | 가설 기각 — 모수화만으로는 안 된다 |
| level 이 선택됨 | Δ 가 val 방향에서 졌다 — test 는 09-24 와 같다. 이것도 결과다 |

### ⚠ 공개해 둘 한계

- **test 는 두 번째로 본다.** Δ 설계는 09-24 test 결과(오차 `열위`)를 보고 나온 것이다.
  선택은 val 로만 하지만, "무엇을 시도할지"가 test 에 조건부라는 사실은 남는다.
  이번 결과가 좋게 나오면 다음 분기 데이터가 들어왔을 때 **새 원점에서 다시 재야**
  확정할 수 있다.
- 방향 축 판정도 함께 바뀔 수 있다. 어느 쪽으로 움직이든 그대로 적는다.

## 0-B. 사전등록 개정 — 재개 전에 확정한 세 가지 (2026-09-27, 결과 보기 **전**)

§1 의 중단 뒤, 재개 **전에** 아래 셋을 확정했다(창업자 결정 2026-09-27). §0 의
"선택 기준은 바꾸지 않는다"를 **대체한다** — Δ 팔은 아직 한 시행도 돌지 않았고,
level 6 시행의 val 값은 09-24 와 같으므로 새로 알게 된 test 정보는 없다. 다만 level
시행의 val 값(§1 표)은 **본 상태에서** 정한 규칙이라는 점을 적어 둔다.

### ① 모델 선택 규칙 — 두 축 조건부

1. 16 시행 중 **val MAE < 같은 val 분할의 지속성 MAE** 인 시행만 후보로 남긴다.
2. 후보 중 **val 방향정확도 최대**(동률이면 val MAE 최소)를 고른다.
3. 후보가 **없으면** val MAE 최소(동률이면 val 방향 최대)를 고르고, 산출물에
   `val 단계에서 이미 지속성 미달` 을 기록한다(`selection.fallback = true`).

근거: 제품이 파는 것은 방향 이분법이 아니라 공실 압력의 **크기**다. 종전 규칙(방향
최대)은 09-24 에 val MAE 1.574 짜리를 두고 1.728 짜리를 골랐다 — 한 기준으로 두
게이트를 노리다 오차 축을 버린 셈이다.

### ② 방향 축 판정 지표 — **원시 정확도 유지**

게이트 판정은 종전대로 원시 방향정확도 vs 무정보 상수(쌍대 차이의 군집 구간 +
McNemar)다. 균형정확도·MCC 는 **관측으로만** 찍는다.

근거: 균형정확도가 유리하게 나온다는 것(62.3% vs 상수 50%)을 **이미 봤다.** 지금
그쪽으로 바꾸면 결과를 알고 지표를 고른 것이 된다.

### ③ `실력` 확정은 **본 적 없는 분기**에서만

- 이미 본 test 분기: **2025Q4 · 2026Q1 · 2026Q2** (09-24 재학습, 각 80건). 산출물
  `protocol.confirm_after = "20262"` 로 박는다.
- 이번 재학습의 test 결과는 **참고 판정**이다. 게이트는 `confirm_after` **이후 분기**의
  holdout 만으로 판정하고, 그런 표본이 없으면 **`확인대기`**(게이트 0)다.
  `scripts/kpi_baseline.py` 가 이 규칙을 집행한다 — 문서가 아니라 판정 코드에 둔다.
- 첫 확정 기회는 2026Q3 분기 데이터가 Gold 에 들어온 뒤의 재학습이다. 그때 새 표본은
  **한 분기(≈80건)** 뿐이라 구간이 넓다 — 첫 확정이 `구분불가`로 나와도 이상하지 않고,
  분기가 쌓일수록(80 → 160 → 240) 좁아진다.

⚠ 따라서 LSTM 두 게이트는 **2026Q3 데이터 이전에는 닫히지 않는다.** Platform 100% 의
하한 시점이 여기서 정해진다.

⑥(지속성을 못 넘을 때 화면에 무엇을 보일지)은 2026Q3 확인 결과를 보고 정한다.

## 1. 1차 시도 — 16 시행 중 6 에서 중단 (2026-09-27 새벽) · 결과는 §2

노트북 재부팅(09-27 06:47 부팅)으로 학습 프로세스가 끊겼다 — 세션 탓이 아니었다. **Δ 팔은 한 시행도 돌지 않았다** — 그리드 순서가
level 8 → delta 8 이라서다. 산출물(`ml/artifacts/vacancy_lstm.pt` ·
`data/gold/platform_vacancy_forecast.json`)은 학습 끝에서만 쓰므로 **09-24 서빙본 그대로**다.
가설은 아직 판정되지 않았다 — 기각도 지지도 아니다.

### 끊기기 전에 얻은 것 — level 6 시행이 09-24 를 그대로 재현했다

| trial | 설정 | val MAE | val 방향 | 09-24 |
|---|---|---|---|---|
| 0 | h32/L1 | 2.046 | 51.9% | 같음 |
| 1 | h64/L1 | 1.995 | 61.9% | 같음 |
| 2 | h64/L2 | 2.055 | 53.8% | 같음 |
| 3 | h32/L1/lb6 | 1.709 | 61.3% | 같음 |

| 5 | h96/L1 | 2.278 | 50.0% | 같음 |

`target_mode` 인자를 들인 코드 경로가 level 에서 **옛 결과를 비트 단위로 바꾸지 않는다**는
확인이다(시드 고정). Δ 팔의 결과가 나오면 차이는 모수화에서만 온다.

### ⚠ 새로 보인 것 — val 에서도 모든 시행이 상수 규칙 아래다

val 분할의 무정보 상수('다수 방향')가 **70.6%** 인데, 6 시행 중 최고(trial 4)가 69.4% 다.
즉 09-24 선택본은 **val 에서도 상수를 못 이긴 채 골라졌다.** 선택 기준이 "val 방향
최대"라 상수 대비를 보지 않기 때문이다. test 방향 +4.6%p 가 `구분불가`로 나온 것과 같은
방향의 신호다. (이때는 "선택 기준은 바꾸지 않는다"고 적었으나, 재개 전에 §0-B ① 로
개정했다 — Δ 팔이 한 시행도 돌기 전이다.)

### 재개하는 법

```bash
OMP_NUM_THREADS=1 PYTHONIOENCODING=utf-8 python -u -m ml.training.train_lstm
```

16 시행을 처음부터 다시 돈다(체크포인트 재개 없음). 09-26 밤 실측으로 시행당 약 5분
(다른 프로세스가 CPU 100% 를 쓰던 상태) — 한가한 머신이면 더 짧다. 절전 억제는
`autorun` 스킬 규칙을 따른다. 끝나면 `python scripts/kpi_baseline.py` 로 판정하고 이 절을 채운다.

## 2. 결과 — 16 시행 완주 (2026-09-27 오전, 세션 밖 분리 실행)

### 가설 기각 — Δ 모수화는 지속성을 기본값으로 만들지 못했다

**16 시행 전부 val 에서 지속성(val MAE 1.338)에 졌다.** 사전등록 ① 의 후보가 0개라
대체 규칙대로 val MAE 최소인 trial 7(level)이 골라졌고 `selection.fallback = true` 가
산출물에 남았다.

| 설정 | level val MAE | Δ val MAE | 나은 쪽 |
|---|---|---|---|
| h32/L1 | **2.046** | 2.072 | level |
| h64/L1 | **1.995** | 2.138 | level |
| h64/L2 | 2.055 | **1.773** | Δ |
| h32/L1/lb6 | **1.709** | 2.046 | level |
| h64/L1/lb10 | **1.728** | 2.124 | level |
| h96/L1 | 2.278 | **2.217** | Δ |
| h96/L1/lb10 | **1.939** | 2.121 | level |
| h64/L1/lb12 | **1.574** | 2.332 | level |

Δ 가 나은 것은 8쌍 중 2쌍뿐이다. level 8 시행은 09-24 를 소수점까지 재현했다.

**왜 기각인가.** Δ 모델은 출력 0 이 곧 지속성인데도 지속성보다 크게 나쁘다(최선 1.773 vs
1.338). 즉 모델이 "변화 없음" 근처에 머물지 않고 **큰 변화량을 자신 있게 틀리게** 낸다.
train 윈도우가 거점당 몇 개뿐이라(`n_train` 396~) 변화량의 잡음을 외우고 있다는 해석과
맞는다. 모수화가 아니라 **학습 표본·정규화**가 병목이라는 쪽으로 무게가 옮겨 간다.

### 선택된 모델의 test — 참고 판정 (사전등록 ③: 본 분기라 확정 아님)

| 축 | 09-24 서빙본 (trial 4) | 이번 (trial 7) |
|---|---|---|
| 선택 근거 | val 방향 최대 | 후보 0/16 → val MAE 최소 |
| 오차 MAE (지속성 1.190) | 2.224 · −86.9% `열위` | **2.065 · −73.5% [−100.4, −47.9] `열위`** |
| 방향 (상수 55.0%) | 59.6% · +4.6%p `구분불가` | **55.8% · +0.8%p [−7.9, +9.6] · p=0.938 `구분불가`** |

MAE 로 고르자 오차는 조금 나아지고 방향 우위는 사라졌다 — 09-24 finding 이 "둘 다 이기는
설정이 그리드에 없다"고 적은 그대로다. 관측: 균형정확도 57.7%(상수 50%) · MCC +0.166.

### 무엇이 바뀌었나 · 안 바뀌었나

- 서빙 산출물(`vacancy_lstm.pt` · `platform_vacancy_forecast.json`)이 trial 7 로 바뀐다.
  브랜치 커밋이라 main 머지 전까지 프로덕션은 09-24 본이다.
- Platform 진행률은 그대로다 — LSTM 두 게이트는 09-26 에도 0 이었고 지금은 `확인대기` 로 0 이다.
