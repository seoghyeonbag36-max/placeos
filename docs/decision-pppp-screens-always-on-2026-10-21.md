### 고친 잠복 결함 — 허브 탭 「지도」가 홈으로 튕김(5판부터)

복구한 뒤 실제 브라우저(Playwright)로 재 보니, 흐름을 **주소로 바로 열었을 때** 허브 탭 「지도」를 누르면
`#/home → #/explore → #/home` 으로 되돌아왔다(데스크톱·휴대폰 모두). `history` 호출에 스택을 걸어 잡은 경로:

1. 탭은 `<a href="#/explore">` 라 **브라우저가** hashchange 를 낸다. 브라우저는 리스너 하나가 끝날 때마다 마이크로태스크를
   돌리고, React 는 hashchange 를 동기(discrete) 우선순위로 처리한다 → 리스너마다 렌더가 따로 커밋된다
2. 흐름을 주소로 바로 열면 흐름 앱(자식)의 리스너가 App(부모)보다 **먼저** 등록된다(effect 는 자식부터)
3. 그래서 흐름 앱이 먼저 `#/explore` 를 보고, 「모르는 흐름 주소 → 홈」 이펙트(`flow/FlowApp.tsx`)로 `#/home` 으로 되감았다.
   App 의 리스너는 그 뒤에 `#/home` 만 봤다

R2·R3 버튼은 `go()` 가 JS 안에서 이벤트를 쏘아 두 갱신이 한 번에 묶였기 때문에 멀쩡했고, 랜딩 → 「시작하기」로 들어온
경우도 App 리스너가 먼저라 멀쩡했다. **로그인 사용자의 첫 화면(흐름 홈)과 새로고침에서만** 터지는 결함이라 테스트(jsdom 은
리스너 사이에 마이크로태스크를 돌리지 않는다)와 같은 페이지 안에서 옮겨 다니는 실화면 검사 모두를 빠져나갔다.

고침: 흐름 앱은 **자기 주소만** 되감는다 — `unknown = !route && (isFlowHash(hash) || (!!token && (hash === "" || hash === "#")))`.
`#/explore`(지도 탐색)·흐름 밖 해시(`#login` · `#admin` …)·로그인 전 빈 해시(랜딩)는 App 이 가른다. 같은 계열로, 주소로 바로
연 흐름에서 브라우저 뒤로가기로 랜딩(빈 해시)에 돌아가지 못하던 경우도 함께 풀린다.

## 3. 규칙

**Platform · Page · Posting · Program 의 구현 화면은 절대 화면에서 제외하지 않는다.**

- **구현 화면** = 지도 탐색(`#/explore` · `App.tsx` 의 `WorkspaceApp`)의 네 트랙 — Platform `PlatformConsole` ·
  Page `MapShell` · Posting `PostingConsole` · Program `CampaignStudio`. 좌측 레일에 PPPP 순서로 늘 넷이 있고, 로그인 없이도 열린다.
- **「제외」로 보는 것 — 전부 금지**
  1. 화면이나 레일 버튼을 지우거나 숨김(조건부 렌더 · `hidden` · 접힌 `<details>` 포함)
  2. 진입로를 다른 곳으로 돌림 — 허브 탭 「지도」 · R2 「지도에서 자세히」 · R3 「지도」는 늘 `#/explore`
  3. 다른 화면(흐름 안 지도 등)으로 갈아끼움
  4. 랜딩의 PPPP 네 질문(`#how`)을 빼거나 접음
  5. 로그인을 요구해 막음
- 새 화면이 같은 질문에 더 잘 답하더라도 **더하지, 대신하지 않는다.** 흐름 안에 지도·목록을 더 두는 것은 괜찮다 —
  단 PPPP 화면으로 가는 길과 그 이름(「지도」)을 가져가지 않는다.
- 진입로가 불편하면(예: 상권이 안 이어짐) 진입로를 돌리지 말고 **PPPP 화면 쪽을 고친다.** §2 의 C2 가 그 예다.
