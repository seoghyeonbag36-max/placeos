## 레시피 이름

건물·층 단위 공실 읽기 레시피 — 흩어진 공개 데이터를 건물 한 채로 묶어 '어느 층이 비었는가'에 답하고, 그 답을 얼마나 믿을지 함께 적는다

## 1. 풀려는 문제

상가 공실은 상권·분기 단위로만 공개됩니다. 그런데 창업자와 행정이 내려야 할 결정은 건물과 층 단위입니다. 건축물대장, 상가정보, 인허가(개·폐업), 임대동향이 서로 다른 기관에서 서로 다른 키와 단위로 공개되어, 한 자리를 판단하려면 사람이 모아 읽어야 합니다. 이 레시피가 푸는 문제는 두 가지입니다.

- **결합**: 흩어진 공개 데이터로 건물·층 단위 공실을 계산할 수 있는가
- **신뢰**: 계산한 값을 어디까지 믿을 수 있는지 어떻게 밝힐 것인가

## 2. 쓰는 데이터

| 자료 | 기관 | 쓰임 |
|---|---|---|
| GIS건물통합정보 | 국토교통부 브이월드 | 건물 윤곽·좌표 |
| 건축물대장(전유부·층별개요) | 국토교통부 건축HUB | 층별 구성 |
| 상가(상권)정보 | 소상공인시장진흥공단 | 점포 위치·업종 |
| 지방행정 인허가 | 행정안전부 | 개·폐업 |
| 상업용부동산 임대동향 | 한국부동산원 | 상권 단위 공실·임대 앵커 |
| 상권분석·생활인구 | 서울 열린데이터광장 | 수요 신호 |

전량 공개 데이터이며 공식 API 로 받습니다. 수집기와 실행 명령이 저장소에 있어 같은 경로로 다시 받을 수 있습니다. 민간 데이터를 크롤링하지 않고, 개인의 신용·거래 정보도 다루지 않습니다.

## 3. 레시피 — 단계마다 입력·출력·확인

| 단계 | 하는 일 | 입력 → 출력 | 어떻게 확인하나 |
|---|---|---|---|
| ① 수집 | 공식 API 로 원본을 받아 가공 없이 보관(Bronze) | 각 기관 API → 원본 | 수집 명령과 입력 묶음을 고정(동결)하고 파일 해시를 남긴다 |
| ② 결합 | 건물 고유번호(PNU) 한 키로 윤곽·층별 구성·영업 점포를 합친다(Silver) | 원본 → 건물 단위 표 | 지번(집계 단위)과 폴리곤(표시 단위)을 구분해 센다 |
| ③ 산출 | 건물·층 단위 공실을 계산한다(Gold). 정보가 부족해 한 층에 배정하지 못하면 범위로 낸다 | 건물 단위 표 → 층별 공실 | 값마다 건축물대장 기반 집계인지 합성 추정인지를 응답 필드로 구분한다 |
| ④ 판정 | 모델 성능을 같은 표본의 무정보 베이스라인과의 차이와 95% 구간으로 쓴다 | 산출물 → 판정 | 구간이 0 을 품으면 '구분 불가'이며 통과가 아니다 |
| ⑤ 재현 | 같은 입력으로 다시 돌려 일치를 본다 | 동결 입력 → 재계산 | `python scripts/kpi_baseline.py` 로 판정을 다시 낸다(읽기 전용) |

## 4. 결과

**범위.** 서울 81거점의 건축물대장 기반 층별 공실 산출물이고, 실제 공실 유닛 인벤토리는 840유닛, 마스터 건물 폴리곤은 52,642개(동결한 입력 묶음 기준)입니다.

| 모델 | 모델 성능 | 같은 표본의 무정보 베이스라인 | 차이 (95% 구간) | 판정 |
|---|---|---|---|---|
| 업종 추천(GNN) · Top-3 | 92.0% | 거점 사전분포 기준선 88.7% | +3.36%p [+2.78, +3.95] | 실력 (시험 17,650자리) |
| 공실 예측(LSTM) · 오차 | MAE 0.822 | 두 무정보 규칙 중 강한 쪽 — 거점 평균 MAE 0.998 (지속성 1.190) | 기술점수 +17.6% [+11.6%, +24.5%] | 참고 판정 · 확정 전 |
| 공실 예측(LSTM) · 방향 | 80.0% (192/240) | 두 무정보 규칙 중 강한 쪽 — '평균 쪽' 규칙 68.8% ('항상 하락' 55.0%) | +11.3%p [+5.4, +17.1] | 참고 판정 · 확정 전 |

업종 추천은 사전분포가 이미 88.7% 를 맞히므로 모델이 더한 몫은 +3.36%p 입니다. 공실 예측은 두 무정보 규칙 중 강한 쪽보다 앞섰지만 아직 확정 전이고, 확정은 모델이 한 번도 보지 않은 2026년 3분기 데이터로만 합니다. 이 표는 업종 추천과 공실 추세의 성능이며 특정 가게의 성패를 맞히는 성능이 아닙니다.

## 5. 이 레시피를 다른 곳에서 쓰려면

- **다른 도시**: 레시피 ①~⑤ 를 그대로 쓰되 서울 전용 소스(서울 열린데이터광장 등)는 도시별로 교체합니다. 거점을 하나 세우는 절차가 문서화된 선형 체인이라 비용을 미리 가늠할 수 있습니다.
- **다른 활용자**: 건물·층 단위 공실과 그 근거 등급을 필요로 하는 곳이면 같은 산출물을 씁니다. 활용 사례는 아직 없고, 이용 기관 확보는 목표일 뿐입니다.
- **개선**: 현장 확인 결과를 독립 검토 표본의 정답으로 쌓아 아래 한계 1을 닫는 것이 첫 과제입니다.

## 6. 한계

1. **건축물대장 기반 산출 공실률의 현실 정확도는 평가하지 못했습니다.** 원천 자료의 관측 시점이 서로 달라 전 거점을 동시점으로 맞출 수 없고, 사람이 정답을 붙일 독립 검토 표본 211개는 아직 전부 미확정(unresolved) 상태입니다. 그래서 '실측'이라 부르지 않습니다.
2. **층 배정에는 범위가 있습니다.** 폭의 중앙값은 16.2%p 이며 통계적 신뢰구간이 아니라 정보 부족에 따른 범위입니다.
3. **업종 추천은 전이적 평가입니다.** 같은 그래프 안에서 층화 분할했으므로 새 거점·미래 시점으로의 일반화는 평가하지 않았고, 기존 점포 업종의 복원이지 신규 입점 성과가 아닙니다.
4. **공실 예측 두 축은 확정 전입니다.**
5. **활용 실적이 없습니다.** 5절의 활용은 계획입니다.
