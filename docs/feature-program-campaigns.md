# Program — 오프라인 캠페인 실행

2026-10-14. 사용자 승인에 따라 기본 Program 화면을 `CampaignStudio`로 전환했다.
기존 팝업·가오픈 생성 API와 `ProgramStudio`는 호환성을 위해 보존하며 기본 진입에서는 사용하지 않는다.

## 구현 범위

1. 매장 운영 여건: 목표, 실제 영업 주소, 대상 고객, 시간대, 수용량, 예산, 제공 가치와 제약을 점주 입력으로 저장한다.
2. 후보·실행안: 공개 행사와 외부 공식 자료 검색을 탐색 진입점으로 제공한다. 후보는 원문 링크·확인일·적합 근거·상호 가치·문의 창구를 입력해야 저장된다. 등록 후보 협업과 자체 실행을 규칙 기반으로 제안한다.
3. 합의·진행: 회차별 조건, 담당자, 다음 행동, 일정, 측정 방법, 중단 조건을 기록한다. 합의와 실제 참여 증빙을 분리하고 협업 회차는 양측 증빙을 요구한다.
4. 비용·결과: 누락 수치는 null로 보존한다. 매출·변동비·실행비가 모두 있을 때만 기록상 잔액을 계산한다. 인과 효과나 예상 매출을 만들지 않는다.

학교·동아리 자동 수집 또는 상대의 참여 의사 자동 확인은 구현 범위에 포함하지 않는다. 공식 자료라도 사용자가 제출한 참고 자료이며 독립 검증으로 표시하지 않는다.

## 투자 판단 계약

- 완료 회차 2개 이상의 점주 참여를 점주 재참여로 집계한다.
- 동일 후보 ID로 완료 회차 2개 이상의 상대 참여를 협업 상대 재참여로 집계한다.
- 점주가 납부한 Program 이용료 중 순결제액이 양수인 완료 회차를 센다. 후속 회차는 이전 완료 회차 종료일 이후 납부한 건만 인정한다. 선납 분할은 재결제로 세지 않는다.
- 결제 의향·취소·전액 환불·행사비·동일 거래 중복은 재결제 증거에서 제외한다. 부분 환불은 원 결제일을 보존한다.
- 같은 상대와 서로 다른 완료 회차에 이용료 납부가 있어야 결합 증거를 표시한다. 만족도는 판정에 사용하지 않는다.
- 결제는 계좌이체 등 **사용자 제출 수동 증빙**이다. PG 실결제나 상대의 직접 인증을 구현한 것이 아니다. 화면에도 독립 검증 전임을 표시한다.

후보를 다른 ID로 다시 등록하면 동일 상대라고 추정하지 않는다. 관찰 기록을 투자 성과의 인과 증거로 해석하지 않는다.

## 저장·배포

- 인증 API: `GET/POST /api/v1/program/campaigns`, `POST /api/v1/program/campaigns/{id}/commands`.
- 사용자별 `program_campaigns` 표, JSON 원장, 버전 비교로 동시 수정 차단, 사용자 삭제 시 함께 삭제.
- 합의 이후 조건은 고정된다. 변경된 조건은 기존 회차 취소 후 새 회차로 기록한다.
- 상태 변경·증빙 정정·환불 이력을 보존한다. 삭제된 외부 링크의 원본을 별도로 보관하지는 않는다.
- 개인정보: 새 표 `program_campaigns` 를 처리방침(`apps/frontend/public/privacy.html` §1·§2, 시행 2026-10-14)과 `PrivacyNote`, `tests/test_privacy_policy_page.py` 의 표 사전에 올렸다. 탈퇴 시 `auth_service.delete_account` 가 함께 지운다. 협업 후보 문의 창구는 제3자 연락처일 수 있어 사업상 창구만 적도록 안내한다.
- 배포 전에 `apps/backend`에서 `alembic upgrade head` 실행 필요. 리비전 `e5f6a7b8c9d0`.
- 이 작업은 로컬 구현이며 운영 DB 변경·배포·커밋·푸시는 하지 않았다.

- `tests/test_campaigns.py`: 출처 필수, 양측 합의, 참여 구분, 미기록/0 구분, 재참여, 재결제, 환불, 선납, 중복 거래, 권한, 버전 충돌, 계정 삭제.
- `tests/test_migration.py::test_migrated_schema_persists_campaign`: 실제 Alembic SQLite 마이그레이션 후 별도 DB 세션 복원. PostgreSQL 운영 검증을 대체하지 않는다.
- `src/pages/CampaignStudio.test.tsx`: 인증, 저장·복원, null/0 전송, 증빙 링크, 충돌 시 입력 보존, 합성 행사 제외, 로그아웃.
- `src/App.test.tsx`: 지도 셸 기본 진입 및 Posting 인계에서 공실 이름을 실제 영업 주소로 사용하지 않음.

테스트의 상호·증빙·거래는 합성 픽스처다. 실제 점주·협업 상대의 재참여나 재결제가 발생했다는 뜻이 아니다.
