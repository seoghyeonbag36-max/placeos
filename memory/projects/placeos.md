# PlaceOS — 프로젝트 마스터 노트

## 정체성
- **한 줄 정의**: 물리적 상권의 리뷰 데이터와 공실 히스토리를 결합하여 디지털 트윈 SaaS로 플랫폼화하는 프로젝트
- **핵심 가설**: "물리적 Place의 가치가 Digital Platform으로 전이되었다" — 물리적 공간을 SNS·디지털 관점에서 하나의 플랫폼으로 읽는다
- **최종 목표**: 18~24개월 내 M&A Exit (네이버·카카오·직방 1순위)
- **자체 평가**: 투자 가능성 92점

## 차별화 포인트
- 기존 상권 분석 시장의 문제: 사후적 지표(카드매출·유동인구)만 의존, 공실 히스토리 단절, 실행 솔루션 부재
- PlaceOS의 답: 과거 폐업 사유 AI 분석 + 건물·층 단위 공실 디지털 트윈 + PPPP 실행 솔루션

## PPPP Framework
사용자가 정의한 4기능. **2026-09-05 재정의로 전통 4P 와 1:1 대응한다**
(Place ▶ Platform · Product ▶ Page · Price ▶ Posting · Promotion ▶ Program).
종전에는 Page 가 Product/Price 를 겸하고 Posting·Program 이 Promotion 하나를 나눠 가졌다 —
Price 를 Posting 으로 넘기면서 "얼마에 팔까"가 아니라 **"어떤 가격대의 page 를 올릴까"** 가 됐다.

### 1. Platform (기능1) — Place ▶ Platform
- **의미**: 이 입지·상권은 **어떤 플랫폼인가**. 물리적 상권마다 하나의 플랫폼화
- **구현**: 상권 AI 추천 엔진 (GNN 기반)
- **출력**: 페르소나·예산·업종 입력 → 적합 상권/입지 Top-K 추천
- **MVP 정확도**: 거점 사전분포 대비 **실력**으로 판정한다(2026-09-16 재정의). Top-3 70% 임계값은 폐기 — 사전분포만으로 89.4% 가 나와 모델을 보증하지 못했다. 현재 값은 `python scripts/kpi_baseline.py` 로 읽는다(09-16 당시 +2.32%p) → `docs/finding-kpi-leak-2026-09-16.md`. ⚠ 이 실력은 노드 단위 업종 예측의 것이지 창업자가 보는 상권 순위의 실력이 아니다(2026-10-19 — CLAUDE.md §KPI①)

### 2. Page (기능2) — Product ▶ Page
- **의미**: 이 platform 안에 **어떤 page 가 만들어져야 하는가**(제품·상품이 아니라 page 다).
  공실 히트맵 + 층별 매물 목록 + 네이버 거리뷰로 "page 자리"를 드러낸다
- **구현**: **네이버 지도**(지도 + 거리뷰 파노라마) + 2D 층 스택 + LSTM 공실 예측
  (Mapbox 는 2026-08-25 제거) · **계획상가(집합건물)는 3D 디지털 트윈**(2026-10-27 결정 · 구현 전 — 실시간 공실 · 건물별 공실 집계로 실제 지역 공실률 · 외부→내부 최적 동선 → 도시재생)
- **출력**: 층 스택 + 거리뷰 + 빨강/노랑/녹색 히트맵 + 건물별 10년 업종 히스토리 + 폐업 사유 LLM 요약
- **MVP 성능**: 지도 로딩 3초(지도 탐색 화면 · `client:map_ready`) — 「건물 상세」는 발신 코드가 0곳이라 KPI 가 아니다(2026-10-19)
- **창업자 답의 정확도**: 빈 층 판정 실력(화면 빈 층 정밀도 − 무정보 기준) — 사전등록 2026-10-19 · 458층 라벨 대기(CLAUDE.md §KPI①)

### 3. Posting (기능3) — Price ▶ Posting
- **의미**: **어떤 가격대의 page 가 이 platform 에 posting 되어야 하는가**. 입점 솔루션 — **외부에서 만든 AI 창업 코파일럿 프로그램을 연동해 적용** (2026-07-18 방향 확정)
- **구현**: `services/posting.py` 어댑터 — `POSTING_COPILOT_URL` 설정 시 외부 코파일럿 호출, 미설정 시 내부 3-Tier(고급화/가성비/기능중심) 비용-효용 계산 폴백
  - 고급화: 객단가 30k, 회전 3회/일, 체류 김
  - 가성비: 객단가 12k, 회전 8회/일
  - 기능중심: 배달 전용, 객단가 18k, 임대료 80% 절감, 고객 비방문
- **출력**: 시나리오별 매출·회수기간(ROI)·리스크. 코파일럿 연동 시 외부 결과를 동일 스키마로 정규화
- **미확정**: 외부 코파일럿의 연동 형태(REST API / 패키지 / 별도 앱) — 확정 시 어댑터 TODO 해소

### 4. Program (기능4) — Promotion ▶ Program
- **의미**: posting 한 page 를 **온·오프라인에서 어떤 홍보 program 으로 돌릴 것인가**. 마케팅 자동화 — 2단계 (2026-07-18 방향 확정)
  1. **가게 단위**: 네이버 지도에 노출되는 상가의 사진·정보·이미지·리뷰 데이터를 활용해 해당 가게의 온/오프라인 마케팅 광고 솔루션 자동 생성
  2. **상권 단위**: Platform에서 수집한 정보(상권분석 시계열·감성·리뷰 키워드)를 바탕으로 상권 마케팅 솔루션 생성
- **구현**: `services/marketing.py` + LLM(Claude vision — 이미지 분석 내장) / LangChain
- **데이터 채널 제약(검증됨)**: 상가 기본정보=네이버 지역검색·카카오 로컬(공식 API), 리뷰성 텍스트=네이버 블로그 검색 API(공식), **플레이스 리뷰·사진은 공식 API 없음** → PoC는 크롤러(약관 리스크 내부 검증 한정), 상용은 점주 제공 데이터(B2B 온보딩 동의) 원칙
- **출력**: 온라인(채널 믹스 + LLM 콘텐츠 + A/B 테스트) / 오프라인(행사·팝업 템플릿 + 상권 적합도 매칭)

## 4단계 확장 로드맵
| Phase | 기간 | 목표 |
|-------|------|------|
| 1 MVP | 1~4개월 | 3개 상권, AI 70%, **2D 층 스택 + 거리뷰**(일반 건물) · 계획상가 3D 디지털 트윈은 2026-10-27 결정(구현 전) |
| 2 확장 | 5~8개월 | 광역시 5개, AI 85%, B2B 대시보드 |

⚠ 이 표의 「AI 70% · 85% · 90%」는 2026-09-16 에 폐기한 임계값이다 — 판정은 베이스라인 대비 실력이다(CLAUDE.md §KPI①).

## 핵심 KPI (고정) — ⚠ 2026-10-19 정체성 정합 검증 결과 **현행 KPI 가 아니다**
현행 KPI 는 CLAUDE.md §KPI Priorities 하나다 — 정체성 「창업자를 위한 부동산 앱」에서 유도한 세 축
(① 답의 실력 · ② 표면 성능 · ③ 고객 검증 — 창업자 파일럿). 아래 표는 2026-05 사업계획 기록이다.
목표 수치는 사용자 결정이라 지우지 않았고, 각 줄이 왜 지금 KPI 가 아닌지만 붙였다
→ docs/finding-kpi-identity-alignment-2026-10-19.md §3

| KPI | 목표 | 2026-10-19 판정 |
|-----|------|------|
| 유료 전환율 | 15%+ | **KPI 아님** — 계측기가 없다(요금 미정 · PG 금지). 지금은 KPI③ 「돈을 낼 의향」만 재고, 실제 결제는 따로 센다(파일럿 킷 ⑥) |
