# PlaceOS API·데이터 확보 체크리스트

작성 기준: 2026-10-09. 대상: 술집, 미용·네일, 옷·잡화, 학원·교육, 운동·여가, 숙박, 전시·공연 및 토지이음 규제 자료.

실제 실행 결과는 [API·데이터 확보 인수서](placeos-data-acquisition-result-2026-10-09.md)를 참조한다. 이 체크리스트의 신청 안내와 실제 승인·수집 상태는 다르다. 나이스·KOPIS 키 발급은 사용자가 직접 담당한다.

### 나이스 인증키 설정 (2026-10-10 확인)

발급받은 인증키는 `data/.env`에 `NEIS_API_KEY=발급받은_인증키`로 설정한다. `OPEN…` 형태의 API ID는 데이터셋 식별자이며 인증키가 아니다. 실제 키는 채팅이나 Git에 넣지 않는다. `data/.env.example`에는 빈 설정 항목을 추가했다. 2026-10-10 08:00 KST에 키 설정과 서울교육청 학원정보 10행 정상 수신을 확인했다. 전량 수집·서비스 연결은 추가 구현 대상이다. [나이스·토지이음 실제 API 확인 결과](api-check-result-2026-10-10.md)를 참조한다.

사용자가 확보할 것은 **API 이용 승인·인증키, 원본 파일, 제공기관 명세, 사업자의 실제 운영·성과자료**다. 파일을 Gold에 직접 넣지 않는다. 신규 자료는 수집·정규화·식별 연결 후 서비스에 반영해야 한다. 아래 저장 위치 중 ‘추가’는 제안 경로이며 연동 완료를 뜻하지 않는다.

## 3. 실제 운영·매출·비용·생존 성과 확보표

공통 요청 기간은 **가능한 과거 월별 자료 전체, 실무 목표는 24개월 이상**이다. 이는 검증 통과를 보장하는 최소 표본 기준이 아니다. 신규 점포는 개업일부터, 폐업 점포는 폐업 전후 자료를 포함한다. 이후 월별 갱신을 협의한다.

| 확인 | 제공자·확보처 | 확보 방법 | 요청할 자료 | 적용 업종·주의점 |
|---|---|---|---|---|
| ☐ | 참여 사업자의 POS·판매관리 공급사 | 사업자가 관리자 메뉴에서 CSV/XLSX 내보내기. 자동화는 공급사에 API 제공·사용권·비용 문의 | 거래일·거래 ID·판매액·할인·취소·환불·결제수단·판매채널 | 술집·소매·미용 등. POS와 카드정산을 합산하면 중복될 수 있음 |

## 4. 자료를 제공자에게 요청할 때 사용할 문구

> PlaceOS의 업종별 운영 분석 및 매출·영업 지속 검증을 위해 자료 제공을 요청드립니다. 가능한 과거 기간 전체(목표 24개월 이상)의 일별 거래 또는 월별 집계, 환불·취소, 비용, 운영 용량·이용 실적, 영업상태 변경자료가 필요합니다. CSV/XLSX 또는 공식 API 제공 가능 여부, 항목 명세, 기준일, 포함·누락 범위, 갱신주기, 이용비용과 서비스·학습·검증 사용 가능 범위를 알려주세요. 고객 이름·전화번호·카드번호 등 개인 식별정보는 요청하지 않습니다. 자료가 없는 기간은 0으로 채우지 말고 미확보로 표시해 주세요.

사업자별 추가 항목: 술집은 좌석·회전율, 미용은 시술 가능 용량·예약률, 소매는 원가·반품·재고, 학원은 정원·재원생·수강기간, 운동은 회원·수업·예약, 숙박은 객실·숙박일·가동률, 문화는 회차·대관·수수료를 요청한다.

## 5. 확보 후 전달·저장 기준

- API는 **서비스 URL, 승인 여부, 명세, 호출 한도, 이용기간**을 기록한다. 키는 채팅·문서·Git에 적지 않고 `data/.env` 등 비공개 설정에 넣는다.
- 기존 키 이름: `DATA_GO_KR_SERVICE_KEY`, `SEOUL_OPENAPI_KEY`, `REB_RONE_API_KEY`. 서비스별 활용신청·권한 확인이 필요하다.
- 나이스·KOPIS의 `NEIS_API_KEY`, `KOPIS_API_KEY`는 신규 수집기용 제안 이름이다. 토지이음 공공데이터포털 API는 해당 서비스 승인 후 공공데이터 키를 사용하고, 별도 발급 경로가 확인될 때만 전용 `EUM_API_KEY`를 연결한다.
- 파일은 제공기관 원본을 보존한다. API 응답 형식을 바꾸거나 파일명을 기존 `stores_raw.json`으로 바꿔 다른 원천을 섞지 않는다.
- 원본과 함께 `출처 URL/기관, 대상 지역, 대상 기간, 수집일, 파일/서비스명, 단위·부가세 기준, 포함범위, 갱신주기, 이용조건`을 전달한다.
- 공공 원본은 지정된 `data/bronze/`에 저장한다. 사업자 매출·사업자번호·계약·회계 원본은 **사업자별 접근권한이 있는 비공개 저장소**에 보관하며 공유 Gold나 Git에 넣지 않는다. 이 업로드·저장 기능은 추가 구현 대상이다.
- 기존 Gold는 직접 덮어쓰지 않는다. 새 원천은 Bronze→Silver→Gold로 정규화·식별 연결·품질 검증 후 반영한다.

## 6. 확보 후 PlaceOS 구현 순서

1. 점포 식별: 상가 ID·인허가 관리번호·사업자·POS ID·장소 ID와 연결 유효기간을 관리한다.
2. 경쟁·수요: 업종 분류·영업상태·상권 경계와 기간별 수요를 연결한다.
3. 규제 검토: 필지·건물·시설 용도와 토지이음 규칙·근거·적용기간을 연결한다.
4. 실제 성과: 비공개 Silver에 점포별 월 매출·비용·운영·상태와 출처·결측을 생성한다.
5. 예측 시점 보존: 계획·추천 당시 입력과 확보 시점을 저장하고 이후 실제 결과와 비교한다.
6. 검증: 시간·지역 분리, 관측 종료 처리, 업종별 표본·폐업 사건 수·오차를 보고한다. 기존 업종 분류 정확도를 매출·생존 성능으로 표시하지 않는다.
7. 공개: 검증된 범위만 API/UI에 반영하고 자료 없는 업종·기간은 미지원으로 표시한다.
